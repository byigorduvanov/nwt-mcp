Тест MCP nwt-data на 300 сесіях

100 різних питань від «клієнтів» (закупівельник, трейдер, аналітик, технолог, дата-інженер, переробник) п'ятьма мовами. Кожне питання — окрема ізольована сесія Claude, яка бачить лише 5 інструментів nwt-data. Три прогони: до виправлень, після першого раунду, після другого.

Підсумок

«Правильних» — автоматична перевірка за еталоном, який порахований із даних, плюс ручний перегляд кожного провалу. Вартість — за цінами API для 100 сесій. Половина питань іде на Haiku, половина на Sonnet; Opus не використовувався.

Статус у трьох прогонах: ✓ правильно, ✗ неправильно, мова — відповідь не тією мовою, ! помилка інструмента. Відповідь і виклики показано з фінального прогону.

Як тестували

  • Кожна сесія — claude -p у порожній тимчасовій папці, без файлів і shell (--tools ""), без наших налаштувань, плагінів і пам'яті; лише MCP-сервер nwt-data. Так працює агент зовнішнього клієнта.
  • Системна підказка клієнта: «асистент з ринкових даних пластикової компанії; відповідай лише з інструментів nwt-data, коротко, мовою питання».
  • Ціни: 39 рядів і 12 437 значень PlasticPortal з нашого краулера на VPS, прив'язані до матеріалів і символів графа. Сервер NWT prod під час тесту був недоступний (SSH — тайм-аут, beta.nwt.one — HTTP 522), у NWT Kit цін немає.
  • Еталони для перевірки пораховані з даних, а не написані руками. Кожен провал і кожну помилку інструмента переглянуто вручну; 6 хибних провалів перевірки виправлено.
  • Обмеження: одна сесія на питання в кожному прогоні, тому окремі коливання (зокрема мова) — це шум моделі в межах кількох відсотків. Токени оцінено як символи / 4.
